# Build Log — bug diary

One line per thing that broke or surprised us: what happened → why → fix.

| When | What happened | Why | Fix |
|---|---|---|---|
| Oct 11 | Global git identity was a placeholder (`Your Name`) | Fresh machine config | Set repo-local `user.name`/`user.email` |
| Oct 11 | Blur check would reject every clear-sky photo | Variance-of-Laplacian is near zero for a smooth blue sky, same as a blurry shot | Skip the blur test for `sky`/`water` tasks; lowered threshold to 25 |
| Oct 11 | Long bash heredoc for `quests.py` failed with "unexpected EOF" | An apostrophe in `bird's nest` inside a nested quoted block | Wrote the file directly instead of via shell |
| Oct 11 | Python edit script crashed with UnicodeDecodeError on app.js | Windows defaults `open()` to cp1252, and the file has emoji | Run tooling with `PYTHONUTF8=1` |
| Oct 11 | Camera overlay covered every screen | `.camera { display: flex }` beats the `hidden` attribute's UA style | Global `[hidden] { display: none !important; }`; caught by a headless screenshot |
| Oct 11 | Tracing outcomes (photo match / no match) never reached Sentry | Callers set the outcome after `gemma.chat` returned, when the span had already closed | `gemma.chat(..., outcome=fn)` labels the result inside the span |
| Oct 11 | Tracing test found no `gen_ai.chat` span in the transaction | sentry-sdk 2.71 streams gen_ai spans as standalone v2 `span` envelope items | Test reads both transaction spans and standalone span items |
| Oct 11 | A blank `ELEVENLABS_VOICE_ID=` in .env would have sent an empty voice ID to ElevenLabs | `os.getenv(key, default)` returns "" when the key exists but is empty | Use `os.getenv(key) or default` |
| Oct 11 | First real Gemma call: plain-text reply ("Enjoy your walk!") instead of the JSON schema | `gemma4:e4b` is a thinking model; with thinking on, the reply sometimes ignored the `format` schema, and it was slow | Send `"think": false`: valid JSON 3/3, about 2 s per reply |
| Oct 11 | Ollama 500: "unable to allocate CPU buffer of size 4448861504" | Only 1.7 GB of 15.7 GB RAM free, and Gemma needs about 4.4 GB to load (Iris Xe GPU, so no VRAM offload) | Closed OneDrive and other apps, then it loaded |
| Oct 11 | Medium "Walk from here" quest came out with 3 tasks instead of 5 | The "no task types from the last 3 quests" rule emptied the seasonal bank; place quests hid it by padding with place tasks | When the bank runs dry, reuse older task types (never twice in one quest) |
| Oct 11 | Running one test file alone wrote 4 test quests and 2 photos into the real `data/` database | Test isolation lived in `test_core.py`; a file that imported the app first loaded the real `.env` (real data folder, real Gemma, real keys) | Moved isolation to `tests/conftest.py`, which asserts it never sees `data/` or real keys; deleted the test rows by ID after a backup |
| Oct 11 | Regex for "no destinations" matched nothing | A shell heredoc turned `\b` into a literal backspace character | Rewrote the escapes; checked no source file has control characters |
| Oct 11 | First real "Walk from here" quest took 114 s | Gemma's first draft had 2 daytime sky tasks at night, so the rules asked for a second draft | Working as designed; noted that quest creation can take 1-2 min on this laptop |
| Oct 11 | Feature: pick photos from the gallery | People walk first and open the app later | Read EXIF time + GPS before stripping. Both present: normal place/time checks, can be fully verified. Either missing: Gemma still checks content, new status "unconfirmed" (time/place not confirmed) completes the task but never counts for badges |
| Oct 11 | A gallery photo could have borrowed the phone's *current* GPS and passed the place check | The upload carried the phone's live fix alongside the file | For gallery photos, place and time come only from the photo's EXIF; the live fix is ignored (tested: phone at the park, photo's EXIF 5 km away fails) |
| Oct 11 | Old "file modified long before the shutter" rule would have failed every gallery photo | It was written for the camera fallback input, where an old file means it came from the gallery | Rule now applies only to the camera fallback (`source=input`) |
| Oct 11 | Two buttons per task squeezed the task text to one word per line | Buttons lived in a side column next to the text | Buttons moved to their own row under the task; caught by a 390 px headless screenshot |
| Oct 11 | Quest started talking the moment you hit Start | Auto-read was always on | Off by default; "Read it to me" buttons on the quest screens; "Read quests aloud as soon as I start" setting saved on the phone and on Base Camp |
| Oct 11 | Feature: notifications (Web Push from Base Camp) | Reminders get you outside without opening the app; the quest notification keeps the phone in your pocket | VAPID keys in `.env`; a background loop sends the daily walk reminder (default 5 PM) and the evening journal reminder (only if no journal note today); a single `wj-quest` notification shows "2 of 5 done" and a Take photo action, updated by the phone and by Base Camp after each verified photo |
| Oct 11 | Installing pywebpush upgraded `cryptography` to 50 and broke `pyopenssl` (needs <48) | pip resolves pywebpush's `cryptography>=47` to the newest | Pinned `cryptography>=47,<48`, which satisfies both; `pip check` clean |
| Oct 11 | VAPID signing failed: "Missing 'sub' from claims" | py_vapid only accepts `mailto:` or a bare `https://host`, not a URL with a path | Default subject is a GitHub no-reply `mailto:` (no real email sent to push services); configurable as `VAPID_SUBJECT` |
| Oct 11 | Switching the daily reminder on at 9 PM would have fired it instantly | "Past 5 PM and not sent today" is true all evening | Only send within the hour after the chosen time |
| Oct 11 | Summary and journal cards suddenly had a dashed border | New `.note` class for the iPhone tip collided with the existing `.card.note` paper style | Renamed it `.ios-note`; caught by a headless screenshot |
| Oct 11 | Notification privacy | Push text passes through Google/Apple/Mozilla push services (encrypted) | `push.assert_private()` refuses any payload with coordinates, places or photo links; tested |
| Oct 11 | Feature: "Swap this task" | A task can be impossible where you are (no pinecones on your street) | Gemma writes ONE replacement from the quest's own context; it goes through the same `check_task()` rules as whole quests (no invented place features, no unsafe tasks, no task types already in the quest). Limits: Easy 1, Medium 2, Hard 2, separate from the Hard skip. Place-specific and rare tasks are replaced in kind. No point penalty. The new task gets a fresh id so old photos never count for it |
| Oct 11 | Refactor: the per-task rules lived inside `enforce_rules()`'s loop | Swaps needed the exact same checks | Extracted `check_task()`; whole quests and swaps share it |
| Oct 11 | Reported deadline times were 7 hours off | Git Bash ignores `TZ=America/Los_Angeles` and silently prints UTC | Use Python `zoneinfo` for any time math; it was 7:58 AM PDT, not 2:58 PM |
| Oct 11 | A tester couldn't change her location | The home location was saved once at setup with no way to update it. Worse, if a GPS request failed, `getFix()` silently returned the last position the page had seen, however old, so "Walk from here" could start from a stale spot | Added "📍 Update my location" (home screen and Settings) that saves a fresh GPS reading and city. "Walk from here" now demands a fresh fix (`maximumAge: 0`) and says so if it can't get one. A failed GPS request returns nothing instead of an old position, so a photo without GPS gets an honest "no GPS fix" instead of borrowing an old location. Static files only, so it went live without restarting Base Camp |
| Oct 11 | Live test: Base Camp stopped at 10:50 PM | The laptop hit critically low memory and Claude Code stopped the background server (not a Walk Journal crash); Gemma's runner died with it mid-check | Photos queue on the phone (offline-first) so nothing was lost. Restarted only the server; the tunnel kept the same link |
| Oct 11 | One photo was checked by Gemma ~9 times in parallel | Every phone sync asked Base Camp to retry *all* pending photos, including ones whose first check was still running; two phones syncing made it worse (92 s checks, memory spikes) | `CHECKING` set: a photo is claimed before its row exists, retries skip claimed photos, `check_once()` guards everything; tested with 5 parallel retries -> 1 Gemma call |
| Oct 11 | Testers created 13 quests but finished 2; Gemma replies climbed to 116 s | Writing a quest takes ~1 min; extra taps on "Walk from here" queued more quests behind it | Quest buttons ignore taps while one is being written (survives a reload for 2 min); loading screen says "Writing your quest, about 1 minute" |
| Oct 11 | Gallery photos always came back "time/place not confirmed" | Diagnosis: the app never recorded which EXIF fields arrived, but 6 of 8 photos were 722x1600/718x1600 (20:9, a phone *screen*), so most were likely screenshots, which have no capture time or GPS. One tester re-picked from the gallery 5 times for one task | Clear message when a photo has no time/location and no more re-picking a ◐ task (Take photo instead). New columns `exif_time`, `exif_gps`, `user_agent` record what actually arrives |
| Oct 11 | Gallery photos with a time but no GPS could never be verified | Many phones strip GPS but keep the capture time | The phone's live GPS at upload now places the photo; EXIF time inside the quest window (or the last 15 min) + live GPS passing the place check = "verified (gallery)" |
| Oct 11 | Friend in Hyderabad got Missouri fall tasks (acorns, red leaves) | Seasons came from the calendar + hemisphere only | Between latitudes -23.5 and 23.5, local seasons: summer / monsoon / post-monsoon / winter (north), wet / dry (south), with tropical tasks (hibiscus, bougainvillea, neem, coconut trees, crows or mynas, rain puddles). Each quest uses the walker's own location |
| Oct 11 | Walks were impossible with location turned off | Every photo needs a place check | No-location walks: everyday tasks only (sky, grass, a road or path, a tree, your shoes, a plant); place check skipped; photos say "place not confirmed" |
| Oct 11 | A walk only "counted" with every task done | All-or-nothing felt like pressure | 75% of tasks (rounded up) completes a walk; below that it's saved as a partial walk in the journal and on the map, without points or badges. Older walks are judged by the same rule without rewriting their rows |
| Oct 11 | Daily streak badges punished rest days | 3-Day/7-Day streaks | Replaced with a weekly goal the walker picks (1-7, default 3): "Week Well Walked" and "Four Good Weeks". No "streak broken" text anywhere; reminders now read "Nice day for a short walk?". Old streak badge rows stay in the database, just not shown |
| Oct 11 | Near miss: a quick import check would have run migrations on the real database | Importing `basecamp.app.main` runs `db.init()` against the configured data folder | Caught before it ran (syntax error stopped it first). All checks now use a temp `DATA_DIR`; migration rehearsed on a copy of the backup before touching real data |
| Oct 11 | A weekly-goal test failed only on this laptop | `time.mktime()` used the laptop's India timezone, moving a date into the previous week | Tests build timestamps in explicit UTC |
| Oct 12 | Journal redesigned as diary pages | Testers' notes deserved a page, not a card | Cream paper with ruled lines and a tiny SVG-noise texture, pixel-font dates/titles (Pixelify Sans, bundled), notes in Cormorant Garamond italic (bundled), season wax seal, polaroid prints with washi tape, gentle "partial walk" stamp, one tiny critter at most. CSS + inline SVG only, no animation, checked at 390 px in light and dusk |
| Oct 12 | A diary page printed the word "undefined" | The critter picker used `>>` on a 32-bit hash; big hashes went negative, so `% 3` gave -1 | Use `>>>` (unsigned) and fall back to no critter; caught in the phone-width screenshot |
| Oct 12 | Testers ran out of swaps and found 75%-rounded-up too strict (3 of 3 on Easy) | Limits 1/2/2 and `ceil` | Swaps Easy 2, Medium 3, Hard 3. 75% now rounds to the nearest task (3 -> 2, 5 -> 4, 7 -> 5). Computed on the fly, so stored walks were relabeled without touching a row |
| Oct 12 | First Gemma call after a quiet hour took ~80 s | Ollama unloads the model after 5 idle minutes by default | Every request sends `keep_alive: "2h"` |
| Oct 12 | A tester's 2 offline photos never arrived | Base Camp was stopped (low memory) while she was out; her quest start and photos are waiting in her phone's queue | Nothing lost: they sync when she opens the app while Base Camp runs. Base Camp now runs in its own window so Claude Code's memory guard can't stop it |
| Oct 12 | The shared link stopped working ("Could not resolve host") though cloudflared was still running | Free quick-tunnel addresses are dropped by Cloudflare once the connection breaks (the laptop changed networks); they never come back | Started a new quick tunnel (new link). Lesson: anything stored on a phone is tied to the link it was opened from, including the offline photo queue, so a stable link (named Cloudflare tunnel) is needed before real use |
